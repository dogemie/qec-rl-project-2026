## 🛠️ 2. 트러블슈팅 1: 보상 체계 및 다중 작업 학습 가중치의 함정

### 📌 증상
* 학습 중 `Val Loss`가 0.0000이 되고, `Pol Loss`가 3.1311 (초기 균등 분포 상태)에 완벽하게 고정됨.
* 동적 가중치 `W_Val`은 21.6배로 폭증한 반면, `W_Pol`은 0.33으로 급락하며 Policy 학습이 완전히 무시되는 현상 발생.

### 🔍 수학적 원인 분석 (Uncertainty Weighting의 한계)
* 컴퓨터 비전 등 지도학습에서 성공했던 논문(Kendall et al.)의 수식 $Loss = \exp(-s) \cdot L + s$ 를 RL에 적용했으나, RL 환경 특성상 AI가 "백지 제출(Submit)" 꼼수를 써서 Value Loss($L$)를 강제로 `0.0000`으로 만들어 버림.
* $L=0$이 되자 지수 함수 방어막($\exp(-s)$)이 무력화되었고, 신경망은 전체 Loss를 깎기 위해 파라미터 $s$를 끝없이 음수로 내리는 데에만 집중함 (Reward Hacking).

### 💡 해결책
* 강화학습 특유의 극단적인 환경 해킹을 방지하기 위해, 기교를 부린 동적 가중치(Uncertainty Weighting) 로직을 모조리 삭제.
* **가장 정직하고 안정적인 1:1 합산 방식(`total_loss = value_loss + policy_loss`)으로 회귀**하여 AI가 꼼수 없이 정책(Policy)을 학습하도록 강제함.

## 🛠️ 3. 트러블슈팅 2: 안정자(Stabilizer) 기하학적 배치 알고리즘 수정

### 📌 증상
* 100 에포크를 돌려도 단 하나의 통과 예제(위반 0개)를 찾지 못함.

### 🔍 원인 분석 (체스판 패턴의 부재)
* 양자 표면 코드(Surface Code)에서 $H_X$와 $H_Z$ 안정자가 교환 법칙(Commute)을 만족하려면, 두 안정자가 정확히 2개의 데이터 큐비트를 공유해야 함.
* 이를 위해서는 X 안정자와 Z 안정자가 반드시 **체스판(Checkerboard) 무늬**처럼 교차로 배치되어야 함 .
* 기존 `_build_topology_mask` 알고리즘은 거리가 가까운 순서대로 앞 절반은 무조건 X, 뒤 절반은 무조건 Z를 할당하여, 수학적으로 교환 법칙 성립이 불가능한 '엉터리 도화지'를 제공했음.

### 💡 해결책
* `envs/qec_env.py`의 토폴로지 마스크 생성 로직 전면 수정.
* 짝수(2n) 위치에 안정자를 배치할 때, 좌표를 기준으로 `(x // 2 + y // 2) % 2 == 0` 조건을 활용하여 **검은 칸에는 X 안정자, 하얀 칸에는 Z 안정자를 할당하는 체스판 분할 배치 알고리즘** 적용.
